# 新表、新背景的宿主全流程

这是当前会话模型要实际执行的写作流程，不依赖CRP示例正文。固定脚本只是适配一个已实现统计范围的助手。新表不必变成示例列名，不能改疾病/指标含义来迁就程序；输入不够时先交安全部分。无需追加外部模型API或独审调用。

1. 使用 `profile.py INPUT --out NEW_JSON`盘点所有工作表，随后用现有本地openpyxl/csv读取与问题相关的单元格。确认标题行、行的临床含义、主键、重复层级、纵向顺序及表间关系。保留原文件快照，不自动合并未知关系，不把结构候选当科学定义。医生只需给目标和自然答复，宿主负责字段映射、脚本与文档。
2. 给医生简短可行性反馈：现在可做、必须确认、可实际补的资料及补后增量、补不到的限制。查询已有答复，集中询问一次；例如没有随访可转为现有横断面/住院描述，但不能默认这些问题已获科学批准。关键方案由医生明确确认，确认记录带原话、时间和来源。
3. 依据新研究问题写本地可重复分析脚本。匹配已有描述适配器才用pipeline analyze；否则在独立研究目录实现所需映射与统计，不引入示例CRP、氧疗、住院事实。只使用已存在且能验证的方法/库；缺方法能力先说明具体缺口，不假装结果已得。分析默认生成适当实际图，保存图点/分箱来源、单位、层级及有效n；合适时用已存在统计库而非自己随意实现复杂推断。
4. 输出通用 `results.json`：键可任意，如 `cohort.n`、`table1.hba1c.median`、`model.or`，不要求示例schema。保存未舍入值、方法与样本口径、缺失、模型限制、图资产哈希及来源。A不把逐行资料送给写作接口，B仅允许项目选择中精确批准的文件/平台/模型/目的。研究目录可保留本地处理数据，按授权范围操作。
5. 以新疾病、新设计、主要结果及方法检索公开文献。优先原始文章、指南和原出版页；逐项核题名/作者/年份/DOI/PMID与摘要或可获全文。讨论中每项“已有研究发现/支持”的主张单独留证据位置、适用人群、与本例可比和不可比处；读不到内容保留缺口，不用身份真实替代内容支持。数量随论证需要，不以堆引用完成任务。
6. 宿主从这些聚合结果实际写出完整中文稿及英文稿；不是要求医生手填模板。包括研究问题与临床背景、已确认方法、结果、摘要、Discussion的主要发现/文献对照/合理解释/临床含义边界、局限、结论、声明和参考文献。两语言先共用结果与论证提纲再分别措辞；禁止虚构伦理、医院、作者、治疗时点或因果。资料不足交“完整可审阅草稿＋明确待核”，不称可投稿。
正文措辞润色仅在引言、方法、结果、Discussion中按SKILL规则执行；摘要、医生沟通、分析和审核报告、投稿信不调用该规则。数值与实质结论先冻结再润色。

7. 根据接口说明构建双语document JSON；研究结果数字用 `{{cohort.n:0}}`这类键/精度绑定，表格从同一结果构建。`compose.py`不生成观点，只导出宿主真实写好的稿。必须核全部结果数字，不能只核已登记占位符；宿主检查正文、摘要、讨论、图注和参考编号。生成DOCX和可支持的PDF，逐页视觉查看，中文优先核字体。
8. 修数据时运行同一已确认方法重算；建立来源哈希、单元格/记录更正及依赖图。差异追踪到受影响字段、图/表、两语言具体段落和格式件。即便显示数字不变，也检查旧逻辑及限制。若科学定义改变，取得新的确认后另立版本。重新执行物化、数字核验和渲染，旧输入/全文保持可恢复。

通用入口与通用物化机制可以处理不同字段/背景；**这份指令本身不构成任意新研究已经通过科学验证的证据**。宿主流程尚未在真人、多专科或复杂模型上验证，不能引用合成描述单例的PASS代替新问题验收。

新顺序必须使用SKILL.md的前置发表评估；原后置文献步骤仅保留为结果解释与缺口复查，不替代最近邻比较。
