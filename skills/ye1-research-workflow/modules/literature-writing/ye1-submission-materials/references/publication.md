# 投稿材料与逐条回复

仅本地草稿，不执行投稿、发信或修改投稿系统。目标刊指南仅在用户提供或实际检索到时按其版本使用；未核具体要求就交通用审阅稿，不能称符合该刊现行字数/声明规则。反防御正文规则不应用于本页输出。

## 投稿材料
从实际稿件提取题名、文章类型、主要发现、适用读者、贡献边界与相关表图，写 Cover letter / Highlights 或用户指定声明草稿。摘要不能简单改称 cover letter；Highlights 简洁描述实际发现，不写保证发表、首次发现或已验证机制（除非证据足够）。未知投稿日期、编辑姓名、目标刊信息保留可读待补项。

作者姓名/排序、通讯信息、全体作者同意、伦理批准或豁免/机构与编号、知情同意、利益冲突、基金、数据可用性、独家投稿/未一稿多投都必须有真实确认。缺失时在草稿相应位置标“待作者确认：…”，不要把“无冲突”“已获批准”“所有作者同意”“未向其他期刊投稿”填作默认声明。通常先交可用草稿与集中待确认清单，不要求每句另批。已有明确答复复用并标对应版本，实际投稿另受用户授权。

## 审稿回复
保留审稿人/意见编号，长意见拆子点但不遗失。对每点区分解释、文字修改、补分析/实验、不能完成或合理不同意。回复必须关联当前修订稿版本、实际章节/段落（只有固定已排版文件才能用精确页行）和真实改动短摘录；无改动的合理说明明确“未修改”与理由，不编位置。

计划完成不是已经完成。需要新增实验/统计时先形成待办与可用现有证据，交分析模块/研究者并获得必要科学确认；没有结果不写 we performed / added / confirmed。已经完成的分析需对应方法、结果文件与修订正文，不能仅有回复语句。部分完成逐项区分。拒绝合理不可行意见时给证据和边界，不为迎合审稿捏造数据、伦理、试验或阳性结果。

交逐条回复草稿、实际修改对照和未完成清单。未完成项明确标 DRAFT_PENDING，不称整封可提交；逐项完成仍不代表已投稿或作者批准。
